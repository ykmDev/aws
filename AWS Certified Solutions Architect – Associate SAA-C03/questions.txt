You have updated an S3 bucket policy to allow IAM users to read/write files in the S3 bucket, 
but one of the users complain that he can't perform a PutObject API call.
What is a possible cause for this? 
1. The s3 bucket policy must be wrong. 
2. The user is lacking permissions 
3.The IAM user must have an explicit DENY in the attached IAM Policy. 
4. You need to contact AWS Support to lift this limit.

ans: 3.
explain: Explicit DENY in an IAM Policy will take precedence over an s3 bucket policy.
AWS checks:
    IAM Policy
    +
    Bucket Policy
    +
    ACL (if enabled)
    +
    Other Policies (SCP, Permission Boundary, etc.)
Suppose Bucket Policy:
    {
    "Effect": "Allow",
    "Action": "s3:PutObject",
    "Principal": "*"
    }

This means Everyone may upload.
Now suppose the IAM Policy attached to Bob is:
    {
        "Effect": "Deny",
        "Action": "s3:PutObject",
        "Resource": "*"
    }

AWS evaluates:
    Bucket Policy
    ALLOW
    +
    IAM Policy
    DENY

Result: DENY

because: Explicit DENY always wins.
